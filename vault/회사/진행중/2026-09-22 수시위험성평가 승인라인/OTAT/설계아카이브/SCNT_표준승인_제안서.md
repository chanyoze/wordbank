# 표준 승인(SCNT) 도입 제안 — 수시위험성평가 + 재사용 표준

> 검토·합의용 제안서 (raw 계획: [SCNT_표준승인_도입계획.md](../구현참고/SCNT_표준승인_도입계획.md))

## 한 줄 요약

수시위험성평가의 **자체 승인 로직을 표준 승인관리(SCNT)로 전면 교체**하고, 동시에 **다른 모듈도 손쉽게 붙일 수 있는 재사용 표준**(FE 헬퍼 · BE 브리지 · 승인패널)을 만든다. **프레임워크 코어(cips.js)는 손대지 않는다.**

---

## 1. 배경 — 왜 하나

- 승인이 필요한 화면마다 **요청·승인·반려·취소 로직을 복붙**하고 있다(DCMT·CESC 등). 모듈마다 거의 같은 코드가 반복돼 **유지보수·일관성**이 떨어진다.
- **수시위험성평가는 표준 승인(SCNT)을 쓰지 않고** 자체 승인(상태코드 `STTS_CD`, 결재자 컬럼 `APPRV_*`, 검토의견 게이트)으로 돌아간다.
- 표준화하면 → **승인 로직은 한 곳**, 새 모듈은 **최소 작업**으로 승인을 탑재.

## 2. 목표

1. 수시위험성평가 → **SCNT 표준 승인**으로 전환 (원청 *Rcpt* + 협력사 *Sub* 동시).
2. **재사용 표준** 수립 → 향후 타 모듈은 "**핸들러 1개 + 화면 한 줄**"로 승인 탑재.
3. **cips.js 코어 불가침** — 영향·회귀 범위 격리.

---

## 3. 핵심 결정 (요약)

| 영역 | 결정 |
|---|---|
| **전략** | 자체 승인 → SCNT **완전 대체** · Rcpt+Sub 동시 · 승인사용대상 코드 1개 공유(잠정 `SFAS_AT`) |
| **표준 형태** | ① FE `cips_sanction.js`(화면 head include, `cips.sanction` 객체) ② **승인패널 wframe** ③ BE `SanctionBridge`(모듈당 핸들러 1개) ④ 등록 가이드 |
| **도메인** | 승인 단위 = 평가서 1건 / 기존 승인 컬럼·옵션 **deprecated** / 상태 = **제네릭 5단계** / 검토의견 = **항목별 유지**(잠정) |
| **워크플로** | 반려·승인취소·대리인·전결·병렬 = **SCNT 네이티브** / 승인라인 = **회사별 커스텀** |
| **데이터** | 호스트 = `TSF_ASSMNT_RECEIVE` / 승인라인·사용대상·결재함·푸시 = **기존 공통 자동** |
| **전환** | 현장(프로젝트)별 "**NEW 승인 사용**" 옵션 토글, 신규만 적용 |

---

## 4. 표준 아키텍처 — "한 번 만들고 재사용"

```
[ 호스트 화면 ]                         [ 표준(공통) ]
 내용 뷰(모듈 고유)
 + <승인패널 wframe/> 한 줄  ───▶  CommonSanctionPanel.xml  ──▶ cips_sanction.js (request/act/cancel)
                                                                     │
 [ 호스트 서비스 ]                                                    ▼
 SanctionTargetHandler 1개  ───▶  SanctionBridge(오케스트레이터) ──▶ CommonSanctionService (SCNT 코어)
   (상태 update + 도메인 검증)
```

**새 모듈이 승인을 붙이는 비용**
- (FE) 화면에 **승인패널 한 줄** + 내용 뷰
- (BE) **핸들러 1개**(자기 상태 update + 검증)
- (Data) 사용대상 코드 등록 + 승인라인 정의(기존 관리화면) + 호스트 컬럼

→ 화면마다 복붙하던 **수십~수백 줄이 사라진다.**

## 5. Before / After (예: 문서관리 DCMT)

| | AS-IS (현재) | TO-BE (표준) |
|---|---|---|
| 승인 엔드포인트 | 모듈마다 컨트롤러 5개 | 제네릭 1쌍 공용 |
| 승인 흐름 | 화면마다 복붙·불일치 | 한 곳에서 1회 |
| 새 모듈 비용 | 컨트롤러+서비스+FE 전부 | **핸들러 1개** |
| 버그 수정 | 화면마다(누락 위험) | 한 곳 → 전체 반영 |

> 핵심: SCNT 코어(`actSanction`/`cancelSanction` 등)는 이미 있다. 표준은 **이미 참조 화면이 하던 조합을 공통으로 끌어올리는 리팩토링**이다(새 마법이 아님).

---

## 6. 수시위험성평가 적용 방식

- 기존 자체 승인(상태코드·결재자 컬럼·승인 버튼) **제거** → SCNT로.
- 호스트 테이블 `TSF_ASSMNT_RECEIVE`: 기존 `STTS_CD`·`APPRV_*` **deprecated**, 신규 `STS_CODE`·`CFM_COMPANY_ID`·`CFM_PROJ_CODE`·`CFM_DEM_SN` 추가(문서관리와 동일 패턴).
- **상태 = 제네릭 5단계**: 10 작성중 / 20 요청·대기 / 30 진행중 / 40 완료 / 50 반려. (세부 단계는 SCNT 단계목록으로 표시)
- **검토의견(항목별)** 은 유지하고, "모든 항목에 검토의견 필수"는 승인요청 전 검증으로 이전.
- 승인라인(요청자→공사팀장→안전팀장→대표)은 **기본 예시**이며 **회사별 커스텀**.

## 7. 공통 영역 변경 — 팀 협의 요청 사항

> 공통 파일은 신중히 다뤄야 하므로, 아래는 **합의 후 반영**합니다(개발자가 패치 제안 → 팀 합의 시점 반영).

1. **`cips.js` 코어 미수정.** 새 폴더 `js/sanction/cips_sanction.js` 추가, 승인 필요한 화면 `<head>`에서 개별 include(전역 `config.xml` 미수정).
2. **BE 브리지는 `module/scnt`** 에 추가(`SanctionBridge` + 핸들러 인터페이스). `CommonSanctionService`는 `module/common` 그대로.
3. **승인패널 wframe** `CommonSanctionPanel.xml`(공통) 신설.
4. **호스트 테이블 컬럼 정리**(deprecated + 신규) — 스키마 변경, 마이그레이션 협조.

## 8. 향후 단계 & 남은 확인

**구현 단계(WBS)**: P0 마스터/DB → P1 BE 공통 → P2 FE 공통 → P3 수시 적용 → P4 검증

**업무/외부 확인 (구현 전/중)**
- 결재자가 **항목별 검토**를 실제로 하는가 (→ 검토의견 단위 최종 확정)
- 승인사용대상 코드의 **공식 명명** (잠정 `SFAS_AT`)
