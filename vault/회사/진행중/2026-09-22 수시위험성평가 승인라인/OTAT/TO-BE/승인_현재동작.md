# 승인 모듈 — 현재 동작 (결정표)

> 주제: 승인 궤도 판정 · 상태명 · 버튼 노출 · 편집권한
> 기준: 2026-09-01
> 정본: 예

🟢 **갱신형 문서다. 동작이 바뀌면 여기를 고친다.**
*왜* 그렇게 됐는지(번복·근거·당시 판단)는 [승인상태_전환명세.md §9](./승인상태_전환명세.md) 가 담는다.
**여기에 이력을 쓰지 않는다** — 사실이 두 곳에 있으면 각자 늙는다.

---

## 1. 한눈에

옵션(`SFAS_OPT_060_003`)을 켠 시점에 회차가 어느 상태였느냐로 갈린다.

| # | 옵션 켤 때 회차 | 원청 상태명 | 협력 상태명 | 접수 | 접수취소 | 전환 버튼 |
|---|---|---|---|:--:|:--:|:--:|
| **S0** | 작성중 (미제출) | 목록에 없음 | `요청대기` | — | — | — |
| **S1** | 제출 · 접수 전 | `미접수` | `제출` | ✅ | — | **✅** |
| **S2** | 접수 완료 | `접수` | `접수` | — | ✅ | **✅** |
| **S3a** | 레거시 접수만 (`30`) | `공사팀장승인대기` | `접수` | — | ✅ | **✅** |
| **S3b** | 레거시 결재 진행 (`40`~`60`) | 레거시 결재 어휘 | `접수` | — | — | ❌ |
| **S4** | 원청 직접 작성 <sub>(자동 승인건 생성 이전분)</sub> | `접수` | `접수` | — | ✅ | **✅** |
| **S4′** | 원청 직접 작성 <sub>(이후)</sub> | `요청대기` | `요청대기` | — | — | ❌ 이미 궤도 |
| **S5** | 전환 후 (승인건 있음) | 승인 상태명 | 승인 상태명 | — | — | ❌ |

> **전환을 막는 것은 둘뿐이다** — 레거시 결재 실적(`40`·`50`·`60`)과 이미 승인 궤도인 회차.

## 2. 판정은 어디서 내리나

**궤도 판정 축은 `CFM_DEM_SN` 유무 하나다.** 옵션은 현장 단위인데 궤도는 회차 단위라,
한 현장·한 기준월 안에 레거시 궤도 · 미승인 · 승인 모듈 회차가 공존할 수 있다.

| 무엇 | 어디서 | 식 |
|---|---|---|
| 상태명 | `SfasRegAtRiskasmtRcptSql.STS_NAME` · `SfasRegAtRiskasmtSubSql.STS_NAME` | `CFM_DEM_SN` 분기가 레거시 30~60 분기보다 **앞** |
| 승인 궤도 여부 (화면) | 양쪽 화면 `fnIsScntRow` | `CFM_DEM_SN` 유무만 |
| 접수 버튼 | `RCPT_BTN_VISIBLE_TF` | 승인건 있으면 `'F'` · `CHECK_TF='F'` 면 `'T'` |
| 접수취소 버튼 | `CHK_CANC_PSBL_TF` | 승인건 있으면 `'F'` · `STTS_CD` 20·30 이면 `'T'` |
| 전환 버튼 | `SCNT_CHG_BTN_TF` | `060_003='T'` **&&** 승인건 없음 **&&** `STTS_CD Not In('40','50','60')` |
| 편집권한 | `UPD_PSBL_TF` | 아래 §4 |
| 레거시 승인자명 ×3 | `APPRV_CONSTR_/SAF_/HDCF_USER_NAME` | **`CFM_DEM_SN Is Null` 일 때만** 표시 |
| 협력 제출/취소 버튼 | `SUB_BTN_TF` · `CANC_BTN_TF` | 승인건 있으면 둘 다 `'F'` |

> 표시 · 잠금 · 진입경로가 **같은 식**을 보므로 어긋나지 않는다.

⚠️ **판정 순서 — 승인건을 먼저 본다.** `STTS_CD='30'` 에서 전환하면 *30 + 승인건 있음* 조합이 실재하므로,
레거시 판정이 `STTS_CD` 를 먼저 보면 승인 모듈 회차가 레거시로 오인되고 **옛 승인자명이 되살아난다.**

## 3. 시나리오별

### S0. 작성중 — 협력이 아직 제출하지 않음

`REGIS` 만 있고 `RECEIVE` 가 없다. 아무 프로세스도 진행하지 않았으므로 **옵션에 맞춰 바로 승인 궤도로 간다.**

| | 원청 | 협력 |
|---|---|---|
| 목록 노출 | **안 뜬다** (`RECEIVE` 없음) | 뜬다 |
| 상태명 | — | **`요청대기`** |
| 편집 | — | 가능 |
| 외곽 버튼 | — | **없음** (`SUB_BTN_TF`·`CANC_BTN_TF` 둘 다 `'F'`) |
| 진입 | — | **상태명 링크** → 승인 팝업 |

> 협력이 제출하는 순간 그것이 곧 승인요청이다.

### S1. 제출 · 접수 전 — 협력이 냈고 원청이 아직 안 받음

`REGIS.CHECK_TF='T'` · `RECEIVE.CHECK_TF='F'` · `STTS_CD='10'`

| | 원청 | 협력 |
|---|---|---|
| 상태명 | **`미접수`** | **`제출`** |
| 상태명 링크 | ❌ | ❌ |
| 편집 | ✅ **가능** | ❌ 잠김 |
| **접수 버튼** | ✅ **노출** | — |
| **승인전환 버튼** | ✅ **노출** | — |
| 취소 버튼 | — | 노출 → 레거시 제출취소 |

원청이 편집 가능한 이유 — 협력이 제출한 이상 요청이 있었던 것으로 보아 `승인대기` 와 같은 권한을 준다.

협력이 취소하면 `작성중` 으로 돌아가 **S0** 이 되고, 협력이 스스로 승인요청할 수 있다.
버튼 라벨은 `제출취소` 이고 동작도 레거시 제출취소다 — 어긋나지 않는다.

### S2. 접수 완료 — 원청이 접수까지 누름

`RECEIVE.CHECK_TF='T'` · `STTS_CD='20'`

| | 원청 | 협력 |
|---|---|---|
| 상태명 | **`접수`** | **`접수`** |
| 상태명 링크 | ❌ | ❌ |
| 편집 | ✅ 가능 | ❌ 잠김 |
| **접수취소** | ✅ **노출** | — |
| **승인전환 버튼** | ✅ **노출** | — |
| 취소 버튼 | — | 노출(`제출취소`) → 화면에서 차단 |

**전환 버튼과 접수취소 버튼이 나란히 뜬다** — 원청이 *"승인으로 올릴지 / 접수를 무를지"* 를 고른다.

협력은 손댈 수 없다. 접수된 회차는 제출취소가 막혀 있다 — `wbtnCancel_onclick` 이 `RCPT_TF='T'` 를 보고
*"건설사에서 접수하여 제출을 취소할 수 없습니다"* 로 되돌린다(PL/SQL `ORA-20009` 까지 가지 않는다).
라벨(`제출취소`)과 문구가 같은 어휘라 어긋나지 않는다.

### S3. 레거시 결재 — 실적 유무로 갈린다

`STTS_CD='30'`(공사팀장승인대기)은 **결재 실적이 0건**이다. 원청이 접수만 했고 `APPRV_C_TF` 가 `'F'` 다.
소급유지의 목적은 *진행 중이던 결재가 끊기는 것*을 막는 것 하나이므로, 실적 0건은 대상이 아니다.

#### S3a. `STTS_CD='30'` — 접수만 함

| | 원청 | 협력 |
|---|---|---|
| 상태명 | `공사팀장승인대기` | `접수` |
| 편집 | ✅ **전원** | ❌ 잠김 |
| 접수취소 | ✅ 노출 | — |
| **승인전환 버튼** | ✅ **노출** | — |

레거시 승인처리와 승인전환이 **같이** 뜬다 — 원청이 고르는 자리다.

> ⚠️ **전환하면 레거시로 못 돌아온다.** 승인요청 시 `updateReceiveState` 가 `STTS_CD` 를 `'20'` 으로 내리고,
> 요청취소·반려해도 되돌리지 않는다. 레거시 결재자 지정값(`APPRV_*_USER_NO`)은 남지만 화면에서 숨겨진다.

#### S3b. `STTS_CD` 40~60 — 결재가 실제로 진행 중

**여기가 유일한 진짜 소급유지다.**

| | 원청 | 협력 |
|---|---|---|
| 상태명 | **레거시 결재 어휘** (`안전팀장승인대기` 등) | `접수` |
| 승인 버튼 | ✅ 레거시 승인처리 · 승인취소 | — |
| **승인전환 버튼** | ❌ **미노출** | — |
| 편집 | 자기 차례 결재자만 | ❌ 잠김 |

승인 모듈로 옮길 수 없다. 레거시 결재를 끝까지 태운다.

### S4 / S4′. 원청 직접 작성

원청 접수화면이 `RECEIVE` 와 `REGIS` 를 **한 트랜잭션에서 함께** 만든다(`insertAsmt`). `CHECK_TF='T'` · `STTS_CD='20'` 으로 시작한다.

| | S4 <sub>자동 승인건 생성 이전분</sub> | S4′ <sub>이후</sub> |
|---|---|---|
| 승인건 | 없음 | **함께 생성** (`createDemandOnNewAsmt`) |
| 상태명 | `접수` | **`요청대기`** |
| 상태명 링크 | ❌ | ✅ 승인 팝업 |
| 접수취소 | ✅ | ❌ |
| **승인전환 버튼** | ✅ | ❌ 이미 궤도 |

S4 는 **S2 와 데이터가 구별되지 않는다.** `REGIS` 유무도 `REGIS.CHECK_TF` 도 판별력이 없다.
둘 다 전환 버튼이 뜨므로 실무상 문제가 되지 않는다 — 원청이 누르면 궤도로 올라간다.

S4′ 는 표준 승인선까지 저장된 채 태어난다. 팝업에서 승인자를 바꿔 재저장할 수 있고, 그 자리에서 승인요청이 된다.

### S5. 전환 후 — 승인건이 생긴 회차

`CFM_DEM_SN` 이 채워진 순간부터 **옵션과 무관하게** 승인 궤도다.

| | 원청 | 협력 |
|---|---|---|
| 상태명 | 승인 상태명 | 승인 상태명 |
| 상태명 링크 | ✅ 승인 팝업 | ✅ 승인 팝업 |
| **승인전환 버튼** | ❌ 사라짐 | — |
| 접수·접수취소 | ❌ 둘 다 | — |
| 제출·제출취소 | — | ❌ 둘 다 |

**접수 컬럼** — 승인요청 시 `CHECK_TF='T'` · `STTS_CD='20'` · 접수자 = 요청자로 맞춘다. 제출본 `CHECK_TF` 도 함께 `'T'`.

**전환 시작 상태는 `요청대기`(`REG`)다.** `승인대기`(`DEM`) 로 올리는 것은 결정됐으나 **제출자 백필이 선행**이다.

## 4. 편집권한 · 삭제

### 편집 (`UPD_PSBL_TF`)

| 상태 | 고칠 수 있는 사람 |
|---|---|
| `요청대기` · `승인반려` | 전원 |
| `승인대기` | 전원 |
| `승인중` | **미처리 단계 승인자 + 대리인만** |
| `승인완료` | 아무도 |

### 삭제

| | 삭제 가능 |
|---|---|
| 원청 | `요청대기` · `승인대기` · `승인반려` |
| 협력 | **`요청대기`만** (반려도 불가) |

`승인중`·`승인완료`는 수정권자여도 막힌다. 화면 게이트를 우회해도 코어가 `-20009` 로 막는다.
평가서를 지우면 승인요청·승인단계도 함께 지운다.

## 5. 요청자

승인 모듈에서 요청자는 **이 평가서를 낸 사람**이다.

| 순서 | 무엇 |
|--:|---|
| 1 | 표준 승인선 조회 — 요청 단계 승인자에 세션이 채워져 나온다 |
| 2 | **제출자로 교체** → 화면에 제출자가 뜬다 (`onStdStepLoaded`) |
| 3 | 원하지 않으면 원청이 **다른 사람으로 변경** |
| 4 | 저장 — **화면의 요청 단계 승인자**를 그대로 요청자(`RP_*`)로 (`beforeDemand`) |

- 2 는 **기본값 제안일 뿐**이다. 3에서 바꿨다면 그것이 원청의 의도이므로 서버가 되돌리지 않는다.
- 승인라인을 바꿔도 같은 보정이 걸린다.
- 제출자 소속과 세션 소속이 **같으면** 손대지 않는다 — 같은 회사 안의 위임은 정상이다.
- 제출자가 비어 있으면(백필 전·원청 직접 작성분) 세션이 요청자다.

> 요청자가 세션과 달라도 승인요청은 막히지 않는다. 요청 단계는 사용자 검사를 통과하고,
> 승인자≠실행자면 `ACT_CODE='AGT'`(대리) · `ACT_USER_NO`=실행자로 기록된다.

## 6. 원청이 고르는 지점은 하나다

S1 · S2 · S3a · S4 에서 원청은 **현상 유지**와 **전환** 중 하나를 고른다.
**전환하지 않으면 회차는 접수 흐름 그대로 굴러간다** — 옵션을 켰다는 이유로 달라지는 것이 없다.

| 시나리오 | 원청 선택 | 협력 개입 |
|---|---|---|
| S0 작성중 | — | ✅ 협력이 제출 = 승인요청 |
| S1 제출 | 현상 유지 / 전환 | ✅ **제출취소하면 `요청대기` 가 되어 협력이 스스로 요청할 수 있다** |
| S2 접수 | 현상 유지 / 전환 | ❌ 없음 |
| S3a 레거시 접수(`30`) | 현상 유지 / 전환 | ❌ 없음 |
| S3b 레거시 결재(`40`~) | — (전환 불가) | ❌ 없음 |
| S4 원청 작성 | 현상 유지 / 전환 | ❌ 없음 |
| S4′ 원청 작성(신규) | — (이미 궤도) | 승인 궤도 참여 |
| S5 전환 후 | — (되돌리기 없음) | 승인 궤도 참여 |

> ⚠️ **S1(미접수)만 협력이 개입할 수 있다.** 접수 전이라 제출취소가 막혀 있지 않고,
> 취소하면 `작성중` 이 아니라 **`요청대기`** 가 되어 협력이 스스로 승인요청할 수 있다.
> **접수된 뒤(S2 · S3 · S4)부터가 원청 전용**이다.
