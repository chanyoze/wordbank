# 상시·수시위험성평가 승인 팝업 — 옵션별 처리 · 컬럼/쿼리 결정 산출물

> **마일스톤**: [ATMS26-012] 한화오션(주) 상시·수시위험성평가 승인모듈
> **대상 화면**: `SfasPopRegRiskAssessmentConfirm.xml` (승인 팝업, 조회 전용)
> **원천**: `SfasRegAtRiskasmtRcpt`(수시위험성평가서접수) 화면·쿼리 이식
> **성격**: 승인 팝업에서 **무엇을·왜** 드러냈/숨겼/삭제했는지 기록하는 살아있는 산출물. 결정이 추가되면 계속 갱신.
> **작성**: 2026-07-08 / 이찬호
>
> 🔧 **정정(2026-07-20 이후 반영)**: ①**APPRV_CMT(현장소장 의견)는 SCNT 팝업에서 완전 제거됨** — 아래 §1 "항상 표시" 목록과 §2-4 textarea 목록의 APPRV_CMT는 무효(060/060_003 공존 안 함). ②역기록 매퍼는 `SfasAtRiskasmtSanctionMapper`/`updateCfmDemand`(§3-5·이력#13) → 현재 **`SfasAtRiskasmtSanctionHandlerMapper`의 `updateCfmReceive`+`updateCfmRegis`**(RECEIVE·REGIS 양 테이블 기록)로 대체됨.

## 1. 수시 옵션별 tr/컬럼 노출 처리 (rowVisibleControl)

## 3-2. FE 데이터 배선 (initW `setOption`/`setDatasets`) — 2026-07-09

### 추가한 model 구성 (팝업 XML) — 2026-07-09 재정리
- **선언 순서(맵-리스트 커플링)**: 코드데이터(`wdmScCdOpt`+`wdlCdOpt`) → 공통조건 `wdmScAll`+`wdlAsmt` → `wdmScCont`+`wdlCont` → `wdmScConstrRvw`+`wdlConstrRvw` → `wdmScSafRvw`+`wdlSafRvw`. 각 dataMap을 짝 dataList **바로 위**에 배치.

## 3-3. `selectAsmt` 쿼리 분석·리폼 — 2026-07-09

### 파라미터 분석 (리폼 전 8종)
| 파라미터 | 성격 | 판정 |
|---|---|---|
| COMPANY_ID·PROJ_CODE·R_COMPANY_ID | WHERE 필터(PK 일부) | **유지** |
| COND_MONTH·COND_DEGREE·EMPHS_TF | WHERE 필터(목록검색: 월/회차/중점) | **제거**(단건 팝업엔 불필요) |
| SESSION_USER_NO(16)·SESSION_COMPANY_ID(1) | SELECT 컬럼용(060 승인선·근로자·직책) | 호출자 파라미터 **아님** — `UserInfo.toMapping()` 서버 주입. 손 안 댐 |

> **핵심**: "4개 PK만으로 조회"는 **WHERE절만 고치면 달성**. 세션값은 서버 자동주입이라 호출자가 넘길 필요 없음(Rcpt 컨트롤러도 SESSION_* 미전달).

### 적용한 리폼 (✅ 완료)

- 그리드 컴포넌트 **id = `wgrdFile`**(← `wgrdSanctnStep` 전체 리네임, 8곳). `scwin.oConfig = {sPreviewDirection:"bottom", nBottomPreviewHeight:0}`.
- build를 `fnEnsureSanctionLib`(async) **밖 동기로** 빼서 호스트 build 전에 그리드 준비.
- **각 화면은 자기 `oAutoFitHeight`에 `wfrmSanctnGrid` 한 줄(nFixSize)만** 추가 = 모듈별 상수 주입(님 요구 그대로). 반응형 원하면 fixSize 목록에서 빼면 잔여공간 자동배분.

**근본원인 (cips.js 코드 분석)**:
- `cips.js:1738` — `getPluginName()=="wframe" → "fileWFrame"` **하드코딩**. 모든 wframe을 파일프레임 취급, **비파일 wframe용 분기 없음**.
- 리사이즈(3494/7633/7680): `wframe.getWindow().wgrdFile.setSize(...)` + `scwin.oConfig.sPreviewDirection` 참조.

**실패 시도(고민 흔적 5회)**:
1. **wframe 내부 oAutoFitHeight** — iframe 경계로 호스트 컴포넌트 참조 불가 + build 시점 iframe 높이 부정확 + 리사이즈 이벤트 미전파. 폐기.
2. **호스트 oManualComponents에 wframe 추가** → `sPreviewDirection` undefined 크래시(oConfig 없음).
3. **`scwin.oConfig` 추가** → `wgrdFile.setSize` undefined(파일 그리드 없음).
4. **`window.wgrdFile = wgrdSanctnStep` 별칭** → 여전히 undefined. `getWindow().scwin.oConfig`는 읽히는데 `getWindow().wgrdFile`만 안 됨 → **`window.x` 수동 할당은 `getWindow()` 객체에 안 얹힘. WebSquare는 컴포넌트 id만 거기 등록** (결정적 발견).
5. **build 동기화**(async 밖) → 그리드는 먼저 준비되나 위 4 근본원인 그대로.
- **해결(5회차)**: 그리드 **컴포넌트 id 자체를 `wgrdFile`로** → WebSquare가 `getWindow()`에 자동 등록 → 네이티브 해석(파일wframe과 동일 메커니즘). ✅

**남은 주의**: 탭 content `cttSanctn`가 `height:500px` 고정이라 **큰 화면에서 500px 초과분 잘림 가능** → 필요 시 그 고정 제거. `wgrdFile`이란 이름은 승인 그리드엔 어색하나 cips.js 하드코딩 요구라 불가피(주석 명시).

## 3-11. 요청자 버튼 흐름 + 액션 팝업 close/캐시 근본원인 — 2026-07-10

**버튼 노출·게이트 (deny-by-default)**
- 버튼 목록은 `scwin.oSanctnButtons` 한 곳(`{sId, sPsblTf, bNeedSave, sAction}` ×5). 노출은 **플래그 'T'만 display:""**(disabled 아님 — 님 피드백). 컴포넌트 조회는 **`$p.getComponentById(id)`**(scwin/window 속성엔 WebSquare 컴포넌트 안 얹힘 — [FLAG]로그로 확정).
- 승인요청은 `bNeedSave` → **dirty 게이트**(`cips.isAllDataModify`): 미저장 변경 있으면 "먼저 저장" 차단.
- 클릭 위임 체인: 버튼 onclick `scwin.onSanctnBtn` → **호스트 `fnRunAction`**(액션을 호스트 스코프에서 실행). 의견팝업/confirm을 **중첩 wframe에서 열면 close가 깨짐** → 반드시 호스트에서 오픈.

**액션 팝업 close 시 `action of null` (승인요청·요청취소 공통 근본원인)**
- `com._closePopup`(common.js:2254)은 close 콜백을 **동기 try/catch로 실행**. 콜백이 그 안에서 `executeSubmissionDynamic`을 호출하면 **닫히는 팝업 컨텍스트의 `.action`을 null로 읽어** throw → 이게 wframe 트리를 깨서 후속 클릭이 `onSanctnBtn is not a function` + `index_tabControl getSrc` 연쇄에러.
- **해법: 제출을 `setTimeout(fn, 0)`으로 팝업 close 완료 뒤로 지연**. 의견팝업(`_openOpinion`)·confirm(`cancel`) 양쪽 동일 적용. (골드레퍼런스 `CescPopRegCompanyEquipmentSafetyCheck`는 **사전선언 `executeSubmission`**을 써서 이 null 경로를 안 타므로 setTimeout 불필요 — 우리는 제네릭 브리지라 dynamic이라 지연 필요.)

**액션 팝업 open 시 콘솔 `onSanctnBtn is not a function` 1회 (동작 무해)**
- `cips.openPopup`은 **동기 빌드**(selectProgram `async[false]`→build ready가 클릭 스택 안에서 완료). 빌드 도중 WebSquare 현재 scope가 팝업으로 이동 → **클릭 디스패치가 아직 안 끝난 채** 버튼 `ev:onclick` 문자열(`scwin.onSanctnBtn`)을 **팝업 scwin 기준으로 1회 재해석** → not a function 로그. 원래 핸들러는 이어져 팝업 정상 오픈이라 **무해**(close측 setTimeout과 동종 = 팝업 open/close가 이벤트 처리 도중 실행됨).
- **해법: `onSanctnBtn`에서 `fnRunAction`(모달 오픈)을 `setTimeout(0)`으로 클릭 디스패치 밖으로 지연** + `bActionBusy` 재진입가드(중복 오픈 방지). 클릭 처리가 먼저 끝나 재해석 소멸.

**⚠️ "고쳤는데 안 바뀜"의 진범 = 전역 메모리 재사용 (재발주의)**
- `cips.sanction`은 **window 전역**. 세 wframe(`fnEnsureSanctionLib`)이 `if(window.cips.sanction){재사용}` 가드로 **최상위 페이지 풀 리로드 전엔 옛 함수 객체를 계속 씀** → 팝업 재오픈·부분 새로고침으론 신규 JS가 안 물림.
- 증상 감별: 콘솔 팝업 프레임에서 `cips.sanction.cancel.toString().includes("setTimeout")` → `false`면 stale.
- **영구조치**: 3곳 로더 `<script src>`에 **`?v=" + new Date().getTime()` cache-bust** → 풀 리로드 때 항상 서버 최신본. 단 메모리 재사용 특성상 **lib 수정 후엔 팝업 재오픈이 아니라 메인앱 Ctrl+F5(풀 리로드)** 필요.
