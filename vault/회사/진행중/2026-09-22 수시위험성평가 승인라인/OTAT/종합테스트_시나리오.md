## S0. 🔴 식별자 리네임 체인 스모크 — 먼저 5분

2026-08-12 커밋으로 **데이터셋 이름 4종·승인팝업 1종**이 바뀌었습니다. 화면 → 액션URL → Controller 응답키 → Service → Mapper → SQL 이 한 줄로 이어지는데, **한 곳만 어긋나면 조회는 성공하고 목록만 텅 빕니다.** 에러가 안 나므로 눈으로 봐야 합니다.

여기서 하나라도 비면 **아래 세션은 전부 노이즈**가 되니 먼저 확인하세요.

| 확인 | 무엇이 걸려 있나 | 비면 의심할 곳 |
|---|---|---|
| [ ] 내용 그리드 **빈도 콤보**에 목록이 뜬다 | `CdFqc → CdFq` | Controller `setData("wdlCdFq")` |
| [ ] 내용 그리드 **강도 콤보**에 목록이 뜬다 | `CdStrth → CdStr` | 〃 `setData("wdlCdStr")` |
| [ ] 조회조건 **회차 콤보**에 목록이 뜬다 | `CdRegDegree → CdStdTime` | 〃 `setData("wdlCdStdTime")` |
| [ ] 재해형태 선택 후 저장 → 에러 없음 | `SumOfDisasterForm → SumOfDrForm` | `executeSumOfDrForm` 체인 |
| [ ] **승인팝업 진입** → 평가서 헤더·내용 그리드가 채워진다 | `Asmnt → Asmt` | `SfasPopRegRiskAssessmentConfirmController` `setData("wdlAsmt")` |

> ⚠️ **톰캣 재기동 필수** — Java 6개(접수 4 + 팝업 컨트롤러 계열)가 바뀌었습니다. 재기동 없이 보면 옛 엔드포인트가 남아 있어 판단이 틀어집니다.

### S2-2b. ⭐ 감소조치자 사번 — 유일하게 "없던 동작이 생기는" 항목

수정 전에는 협력사 쪽 사번이 **항상 null** 이었습니다.

1. 라인추가 → **감소조치자 지정** (반드시 사용자 검색 팝업으로 선택 — 직접 타이핑하면 이름만 들어감) → 저장
2. PMIS4 에서 확인

```sql
Select
    a.REGIS_SEQ,  -- 등록순번
    a.REGIS_DETAIL_SEQ,  -- 등록상세순번
    a.IMPRV_EDU_USER,  -- 감소조치자명
    a.IMPRV_EDU_USER_NO  -- 감소조치자사번
From
    TSF_ASSMNT_REGIS_DETAIL a
Where 1 = 1
And a.CRTDATE >= Trunc(Sysdate)
Order By
    a.REGIS_DETAIL_SEQ Desc
```

- [ ] 이름·사번이 **둘 다** 채워진다 (사번만 비어 있으면 실패)
