### 4-2. ✅ 그리드 헤더 id(`GH_*`) 정렬 — 2026-08-10 적용 완료

`GH_*` 는 헤더 밴드 전용 id 라 데이터 바인딩이 아니다. 선언과 참조(표시제어 배열)를 **함께** 신규명으로 정렬했다 — 본체 47종 62회 + 승인팝업 24종 30회 = **92회**.

> DRY-RUN 에서 **연쇄 치환**(`GH_WK_ATDT_STS_STS`)이 잡혀 단일 패스로 재작성했다 → 함정15.
> 헤더 밴드 단위 중복 검사에서 신규 중복 0건 확인 → 함정16.

### 🟡 발견 — 판단 필요 (전부 기존, 리네임 무관)

**① `bAiLoading` 이 예외 시 켜진 채로 남는다** — [3161~3218](../../src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml#L3161)

```js
scwin.bAiLoading = true;
for(…) { cips.getSequence(…); wdlCont.setCellData(…) × 25; }   // ← 중간에 throw 하면
scwin.bAiLoading = false;                                       // ← 여기 도달 못 함
```
`bAiLoading` 이 true 로 남으면 [2358](../../src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml#L2358) 의 가드가 계속 걸려 **`wdlCont` 의 `onCellDataChange` 가 영구 무력화**된다 → 내용 수정 감지·연동 로직이 화면 새로고침 전까지 죽는다.
→ **권고: `try { … } finally { scwin.bAiLoading = false; }`** (3줄)

**② AI작성 콜백이 `bContModifiedTf` 를 안 켠다** — [3138](../../src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml#L3138)

`bContModifiedTf` 는 보통 `onCellDataChange`([2369](../../src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml#L2369))가 켜주는데, AI 경로는 `bAiLoading` 으로 그 이벤트를 **의도적으로 막는다**. `insertRow` 직접 호출이라 `addAndIns.onClickAfter` 도 안 탄다.
→ AI 결과에 재해형태순번(`DR_FORM_SN`)이 실려오므로, 저장 후 재해사례 등록여부가 **즉시 갱신되지 않을 수 있다**(다음 조회 시 정상화). 심각도 낮음.
→ 일괄수정(`wbtnBdlUpdAll_onclick_callback`)은 `setCellData` 를 쓰므로 **커버됨**.

**③ 승인 wframe 연결 폴링이 조용히 포기한다** — [905](../../src/main/webapp/wqxml/sfas/SfasPopRegRiskAssessmentConfirm.xml#L905)

`nSanctnBindTry < 50` (~5초) 초과 시 **아무 메시지 없이 중단**. 느린 환경에서 승인 UI 가 안 붙어도 원인을 알 수 없다. → 실패 시 로그/안내 1줄 권고.

**④ `scwin.bUpdPsbl` 죽은 플래그** — [770](../../src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml#L770) 선언만 있고 세팅·읽기 0.
