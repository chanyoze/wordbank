# 단어사전 확정본 → 일괄 리네임 적용 절차 (대비 문서)

> 사용자가 `docs/OTAT/수시 단어사전.xlsx`(팀 검수본)의 **채택 별칭을 확정**하면, 아래 절차로 Controller~SQL~wqxml에 일괄 반영한다.
> 이전 시도에서 발견한 **함정 11종**을 반드시 지킬 것 (안 지키면 조용히 깨짐).

## 0. 도구
- `docs/OTAT/wordbook_rename.js` — **단어경계 안전 치환기** (부분문자열 오염 방지)
- 사용: `node wordbook_rename.js <pairs.tsv(old\tnew)> <file1> [file2 ...]`

## 1. 매핑 추출
확정된 단어사전 xlsx에서 **old(웹 현재별칭) → new(채택 별칭)** 쌍만 추린다.
- 상태가 `제외`/`웹전용(유지)`/`유지`인 행은 제외.
- `채택`이 `(제안)`·`(신조)` 미확정 표시면 제외(확정된 것만).

## 2. 적용 대상 파일
- `src/main/webapp/wqxml/sfas/SfasRegAtRiskasmtRcpt.xml` (dataList id·그리드·JS·combo)
- `src/main/resources/sqlmap/mappers/sfas/SfasRegAtRiskasmtRcptSql.xml` (별칭·`#{}` 바인드)
- `src/main/java/.../web/SfasRegAtRiskasmtRcptController.java` (setData/get 키)
- `src/main/java/.../service/impl/SfasRegAtRiskasmtRcptServiceImpl.java` (맵 키, 있으면)

## 3. ⚠️ 함정 16종 (필수 준수)
1. **SQL의 DB컬럼은 건드리지 않는다.** `a.OLD`(테이블별칭.컬럼)는 실제 DB 컬럼 → 유지. **별칭 위치와 `#{OLD}` 바인드만** 치환. (예: `a.ASSMNT_RANK ASSMNT_RANK_SELECT` 에서 `a.ASSMNT_RANK`는 보존, alias만 변경)
   - 자동화 시: SQL은 `(?<![A-Za-z0-9_.])OLD(?![A-Za-z0-9_])` 로 `.`-선행(DB참조) 제외. 단 INSERT 컬럼목록·`Set OLD=` 바레컬럼은 수동 확인.
2. **`_SELECT`/`_CD` 표시변형 충돌.** `ASSMNT_RANK`(저장값)와 `ASSMNT_RANK_SELECT`(표시)가 **같은 표준명으로 가면 한 dataList에 중복** → 깨짐. 표시변형 명명규칙을 먼저 확정(예: `RISK_GR` vs `RISK_GR_SELECT`). 미확정이면 보류.
3. **기존(pre-existing) 토큰 오염.** 타깃 이름이 dev 원본에 **이미 존재**할 수 있다(레거시 coop/r 혼용 등). 정방향은 안전하나 **역방향(롤백) 시** 그 기존 토큰까지 바꿔버림 → 반드시 `git show HEAD:<file>` 카운트와 대조.
   - 예: `COOP_COMPANY_NAME`(팝업 요청키), `item.WBS_NAME`(수신 프로퍼티)는 컬럼이 아니라 인터페이스 이름 → 보존.
4. **FE↔BE 캐스케이드.** dataList id를 바꾸면 Controller `setData("id")`/`get("id")` 키도 같이 바꿔야 함(응답/요청 바인딩). SQL 별칭 = dataList 컬럼 id = 저장 `#{}` 키가 사슬로 엮임.
5. **공유 저장 프로시저.** `LSPSF_ASSMNT_RECEIVE_DETAIL_I`(원청)/`_REGIS_DETAIL_I`(협력)를 **8개 화면 공유**. 파라미터는 이미 표준어(RISK_GR 등)라 DB는 불변 — Rcpt Sql의 CALL 인자만 맞추면 됨.
6. **접두사 없는 단독 컬럼 라인은 별칭이 아니다.** `\t\tSTAN_DEGREE,` 처럼 **앞이 공백뿐**인 라인은 INSERT 컬럼목록 / `Insert … Select` 의 Select 쪽 / Group By 이며 **실제 DB 컬럼**이다. 후행별칭 규칙을 `^\s*TOKEN,$` 에도 적용하면 INSERT가 전부 `ORA-00904`로 깨진다.
   - 규칙: 후행별칭으로 인정하려면 **토큰 앞에 식(비공백)** 이 있어야 한다 → `^(\s*\S.*?[^A-Za-z0-9_.])(TOKEN)(,?)$`
   - `<delete statementType="CALLABLE">` 안의 PL/SQL `Insert Into 이력 (…) Select (…) From 원본` 은 양쪽 모두 DB 컬럼이므로 **전부 보존**.
7. **인라인뷰 별칭 참조는 DB 컬럼이 아니다.** 함정1("`a.OLD`는 보존")의 **예외**. 서브쿼리가 `… OLD` 로 별칭을 달고 바깥에서 `x.OLD` 로 받는 구조에서는, 안쪽 별칭만 바뀌고 바깥 참조가 남아 `ORA-00904`가 된다.
   - 실제 사고: `selectCdRvwOpChkList` 의 `Sum(x.CHK1) …` ← 안쪽 `Nvl2(…) CHK1` 이 이미 신규명, `selectCdProjRoList` 의 `a.A_USER_NO` ← 안쪽 `SFCC_GetUserByDrCd(…) A_USER_NO` 가 이미 신규명.
   - 자동 치환기로는 판별 불가 → **블록 단위 인라인뷰 별칭 스캔 후 수동 수정**. 안쪽·바깥 이름이 같아지면 바깥 별칭은 군더더기이므로 제거(`a.PROJ_HDCF_USER_NO,`).
8. **⚠️ 가장 위험 — 외부 계약 키는 우리 이름이 아니다.** wqxml의 JS에는 *다른 화면이 정한* 이름이 섞여 있다. 단어경계 치환기는 이걸 구분하지 못하고 조용히 바꿔버린다(에러도 안 남).
   - `aoRtnDat.data.XXX` — **상대 팝업이 반환하는 키**. 그 팝업을 안 고쳤으면 그대로 둬야 한다.
   - `"XXX=wdmScAll.YYY"` (팝업 파라미터) — **왼쪽이 상대 팝업의 파라미터명**, 오른쪽만 우리 컬럼.
   - `sInColMap: "우리컬럼=LOV반환컬럼"` — **오른쪽이 공통 LOV의 컬럼명**. 반대로 `sOutColMap: "LOV파라미터=우리컬럼"` 은 오른쪽이 우리 것.
   - `item.XXX` — 외부 연계 수신 프로퍼티.
   - 실제 사고: `SfasPopRegAssesmentApplyAll`(미변경 팝업)이 반환하는 `ASSMNT_RANK`·`PRIORITY`·`C_USER_NO`·`A_USER_NO`·`STAN_DEGREE` 5종과 LOV `SFAS_RISKGR`의 `ASSMNT_RANK`까지 총 7개소가 잘못 치환됨 → 전부 원복.
   - 검사: `git diff` 에서 `aoRtnDat\.data\.|getPopupParameter|sInColMap|sOutColMap|"[A-Z_]+=w|item\.` 를 grep 해 **전후 쌍**으로 눈검사.
9. **⚠️ 별칭 부여는 "괄호 깊이 0(최상위 Select)"에서만.** 함정7의 근본 해결책. CTE·인라인뷰 **안**에서 `a.OLD,` 에 별칭을 붙이면 그 CTE를 참조하는 모든 바깥 코드(`b.OLD`, `Group By`, `Connect By Prior`, `Not Exists x.OLD`)가 한꺼번에 깨진다.
    - 배치2 첫 시도에서 `selectCdDrCaseRegChkList`(CTE 6단)가 이 방식으로 **전면 파손**됐다. 깊이 0 제한으로 재적용하니 이 쿼리는 **변경 0줄**(원래부터 최상위에서 별칭을 달고 있었음).
    - 판정: 문자열 리터럴·`--` 주석을 제외하고 괄호를 세어, **라인 끝 깊이 == 0** 인 라인만 별칭 규칙 적용. (`End) ALIAS` 처럼 시작 깊이가 1이어도 끝이 0이면 최상위다.)
    - 효과: CTE 내부가 구 이름을 유지하므로 바깥 참조가 전부 그대로 유효하다. 화면에는 최상위 별칭만 신규명으로 나간다.
10. **최상위가 `Select *` / `a.*` 인 쿼리는 예외.** 깊이 0에 컬럼이 없으니 **안쪽 이름이 그대로 화면으로 나간다** → dataList 는 신규명을 기대하므로 값 소실(에러 없음).
    - 처리: 최상위를 명시 컬럼으로 풀거나(`selectCdRvwOpChkList`), 인라인뷰 안에서 별칭을 주고 최상위 참조를 함께 고친다(`selectAsmtList`·팝업 `selectAsmt` 의 `UNQ_KEY` 연결식·`Order By`).
    - 검사: 최상위 Select 절에 `*` / `x.*` 가 있는 쿼리를 먼저 뽑아 별도 처리.
11. **타 화면이 우리 쿼리를 호출할 수 있다.** 출력 별칭을 바꾸면 그 화면이 깨진다. `git grep '<Service|Mapper>' -- src/main/java` 로 소비자를 찾고, 소비자가 세팅하는 dataList의 컬럼 계약을 확인할 것.
   - 실제: `selectCdCondDegreeList` 를 `SfasPopRegAssesmentReciveSubmission`·`SfasPopRtrvAssesmentReciveRptAct` 가 호출(계약 `TIME_CODE`/`TIME_NAME`). 이번엔 그 별칭이 대상이 아니어서 무사했으나 다음 배치에서는 확인 필수.
12. **⚠️ `openPopup` 의 `oData` 객체 키 = 수신 팝업의 계약명.** 함정8의 미발견 갈래. 값(우변)은 우리 컬럼이라 바꾸는 게 맞지만 **키(좌변)는 수신측 `getPopupParameter("키")` 와 글자 그대로 일치해야** 한다. 안 맞으면 `undefined` — **에러 없이 조용히 기본값으로 동작**한다.
    - 실제 사고(배치3a): 9개소가 신규명으로 바뀌어 5개 팝업의 파라미터가 죽음. 그중 `EDIT_TF: "T"` 2곳은 재해사례 팝업이 **편집 가능인데 조회 전용으로 잠기는** 실동작 회귀였다.
    - 검사(자동): `scratchpad/popup_contract.js` — 우리 화면의 모든 `cips.openPopup(url, oOpt, oData)` 에서 `oData` 키를 뽑아 `url` 파일의 `getPopupParameter("…")` 집합과 대조.
    - 🔴 **기준선은 반드시 "단어사전 착수 이전 커밋"으로 잡을 것.** 직전 배치 백업을 기준선으로 쓰면 **앞 배치가 깬 것을 "원래 死 파라미터"로 오분류**한다.
      실제 사고: 배치1이 `STAN_DEGREE: → STD_TIME_CODE:`(제출현황 팝업 발신키)를 바꿔 놓았는데, 배치3a 백업 기준으로 돌려서 5회차 내내 "기존 死 5건"으로 통과시켰다.
      콜리는 `getPopupParameter("STAN_DEGREE")` 를 읽고 **비면 `"1"` 로 기본값** → 제출현황이 **항상 1회차로 조회**되고 있었다(특별회차 +5 계산도 전부 무시).
      ```bash
      git show <착수이전커밋>:<wqxml> > /tmp/base.xml   # 기준선 추출 후 같은 스크립트로 대조
      ```
14. **🔴 치환기의 "절 상태기계"가 스칼라 서브쿼리에서 무너진다.** Select 절 안에 `( Select … From … ) ALIAS,` 가 있으면, 그 안의 `From` 이 `inSelect = false` 로 만들고 **바깥 절로 복귀하지 못한다** → 그 뒤 컬럼 전부가 별칭 부여에서 스킵된다. 데이터셋은 신규명을 기대하는데 SQL은 구명을 뱉으니 **에러 없이 빈칸**이 된다.
    - 실제 사고(배치3a, Oracle 대조로 뒤늦게 발견): `selectAsmtList` 의 `SESSION_DR_CD` 스칼라 서브쿼리 이후 4개 컬럼이 통째로 누락 — `CHECK_CANCEL`(→`CHK_CANC_PSBL_TF`) `R_USER_CMT`(→`SUPV_OP`) `WK_ATDT_TF`(→`WK_ATDT_CMPL_TF`) `WK_DEL_TF`(→`WK_DEL_IMPROP_TF`).
      전부 **옵션이 꺼진 현장에서는 안 보이는 컬럼**이라 수동 테스트를 통과해 버렸다(접수취소 버튼은 060_003 현장에서 어차피 'F').
    - 수정: 깊이별 `inSelect` **스택**을 쓰고, 서브쿼리에서 빠져나오면 바깥 상태를 복원할 것.
    - **검사(필수·유일하게 확실함): Oracle 에 물어본다.** `scratchpad/sqlgen.js <sqlfile> <id>` 로 CDATA·동적태그·바인드를 제거한 `Select * From ( body ) Where Rownum <= 0` 를 만들어 실행하고, 반환된 컬럼명을 `scratchpad/cmpcols.js` 로 데이터셋 컬럼과 대조한다.
      텍스트 검증(태그균형·잔여토큰·바인드↔FE)은 **"SQL이 실행된다"를 증명하지 못한다.**
15. **⚠️ 순차 치환은 '이미 바꾼 결과'를 다시 매칭한다 (연쇄 치환).** 매핑을 하나씩 순서대로 `replace` 하면 앞 규칙의 산출물이 뒤 규칙에 다시 걸린다.
    - 실제 사고(GH_ 정렬 DRY-RUN 에서 포착): `GH_WK_ATDT` →(WK_ATDT 규칙)→ `GH_WK_ATDT_STS` →(다시 WK_ATDT 규칙)→ `GH_WK_ATDT_STS_STS`.
      `GH_APPRV_C_USER_NM_HD` → `GH_APPRV_CONSTR_USER_NAME_HD` →(APPRV 규칙)→ `GH_APPRV_BTN_VISIBLE_TF_CONSTR_USER_NAME_HD`.
    - **해결: 단일 패스.** ① 파일의 토큰을 먼저 수집 → ② 토큰별 목표명을 **1회만** 계산(이미 신규명이면 skip) → ③ 정규식 콜백으로 **한 번에** 교체.
      ```js
      s = s.replace(/(?<![A-Za-z0-9_])GH_([A-Z][A-Z0-9_]*)/g, (m, t) => dict[t] ? 'GH_' + dict[t] : m);
      ```
    - 배치1~5 의 `*_apply.js` 는 KEYS 를 길이 내림차순으로 돌려 접두 겹침은 막았지만, **결과 재매칭은 못 막는다.** 신규명이 구명을 접두로 포함하는 매핑(`DR_CASE_REG→DR_CASE_REG_TF`)이 있으면 반드시 단일 패스로.
16. **id 중복 판정은 '스코프' 단위로.** 그리드 헤더 id(`GH_*`)는 **헤더 밴드 안에서만** 유일하면 된다. 파일 전체로 세면 `GH_COMPANY_ID` 가 4개라 오탐이 난다. 반대로 데이터셋/서브미션 id 는 파일 전역 유일이어야 한다.
13. **문자열 리터럴이 컬럼명과 철자가 같을 수 있다.** 단어경계 치환기는 "값"과 "컬럼 id"를 구분하지 못한다.
    - 실제 사고(배치3a): `wdmTrscApprv.set("TAG", "APPRV")` 의 **값** `"APPRV"` 가 `wdlAsmt` 컬럼 `APPRV` 와 같은 철자라 함께 바뀌어, `trscApprv` PL/SQL이 `If #{TAG} = 'APPRV'` 분기를 못 타고 `Else Raise_Application_Error('평가서상태가 변경되었습니다…')` 로 떨어졌다.
    - 검사(자동): `scratchpad/literal_audit2.js` — 백업 대비 **따옴표 안 내용이 바뀐 줄**만 뽑아, 신규명이 어느 데이터셋에도 컬럼으로 선언돼 있지 않으면 값/계약 자리로 보고 플래그.
    - 곁가지: `oInheritColumns: ["자식컬럼ID=부모컬럼ID"]` 도 양쪽이 서로 다른 데이터셋 소속이라 한쪽만 배치에 들어가면 깨진다 → `scratchpad/inherit_check.js`.

## 4. 검증 (매 배치)
```
node -e '...'  # (a) 잔여 old 토큰 0  (b) dataList 중복컬럼 0  (c) wqxml <script> JS 문법 OK
git show HEAD:<file> 로 pre-existing 토큰 카운트 대조 (함정3)
grep FE target ↔ BE setData/get 키 일치 (함정4)
```

### (이하 착수 전 조사 기록) `R_COMPANY_ID→COOP_COMPANY_ID` 기반 매핑
배치4의 파생형(`EVL_R_COMPANY_ID→FST_COOP_COMPANY_ID`, `PRE_ASSMNT_R_COMPANY_ID→PREV_AT_COOP_COMPANY_ID`, `OTH_R_COMPANY_ID→OT_AT_COOP_COMPANY_ID`)만 적용돼 있고 **기반 매핑은 아직 미적용**.

**🔴 `R_COMPANY_ID` 는 실재 DB 컬럼이다.** Oracle 대조: `R_COMPANY_ID` 139개 테이블 / `COOP_COMPANY_ID` 78개 테이블에 존재.
OTAT 3개 테이블 전부 `R_COMPANY_ID` 보유 — `TSF_ASSMNT_RECEIVE`(협력업체회사ID) `TSF_ASSMNT_RECEIVE_DETAIL`(협력업체회사ID) `TSF_ASSMNT_REGIS`(하청회사ID).
→ **함정1·함정6 적용 대상**. 물리컬럼 형태는 전량 보존해야 하며, 앱 표면(별칭·바인드·데이터셋 id)만 대상이다.

| 형태 | 성격 | Rcpt / Sub | 조치 |
|---|---|---|---|
| `a.R_COMPANY_ID` | 물리컬럼 | 81 / 88 | **보존**(함정1) |
| 단독 라인 `R_COMPANY_ID,` (Insert 컬럼목록·Group By) | 물리컬럼 | 66 / 40 | **보존**(함정6) |
| `#{R_COMPANY_ID}` | 앱 표면 바인드 | 161 / 94 | 치환 대상 |
| wqxml 데이터셋 `id="R_COMPANY_ID"` | 앱 표면 | 72 / 55 (+Confirm팝업 24) | 치환 대상 |
| Select 결과 별칭 | 앱 표면 | 현재 0건 | **신설 필요** — `a.R_COMPANY_ID COOP_COMPANY_ID` |

- 결과 별칭이 0건이라는 게 이 매핑의 특수성이다. 다른 배치는 "이미 있는 별칭을 개명"이었지만 여기는 **별칭을 새로 달아야** 한다 → 함정9(깊이 0 제한)·함정10(`a.*` 최상위) 이 그대로 걸린다.
- 이미 이행된 루프가 섞여 있다: `SfasRegAtRiskasmtRcptSql.xml:752` `x.R_COMPANY_ID COOP_COMPANY_ID` → `:384` `#{item.COOP_COMPANY_ID}`. **부분 이행 상태**이므로 함정3(기존 토큰 오염) 카운트 대조가 필수.
- ⚠️ **바인드만 단독 치환 금지.** 생산자(Select 별칭) → 데이터셋 컬럼 → submission → `#{}` 가 한 루프다. 생산자가 아직 `R_COMPANY_ID` 인데 `#{COOP_COMPANY_ID}` 로 바꾸면 MyBatis 가 없는 키를 Null 바인드해 **에러 없이 0건**이 된다(함정4). 161건은 161개 편집이 아니라 **N개 루프** — 배치 단위는 루프여야 한다.
- 저장소 전역 `R_COMPANY_ID` 는 482개 파일에 걸쳐 있다. **OTAT 범위 밖은 이 배치 대상이 아니다.**
